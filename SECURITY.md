# Security policy

## Reporting a vulnerability

Do not open a public issue for anything that could be a security
vulnerability.

Report vulnerabilities privately through GitHub instead: open the
repository's Security tab and use "Report a vulnerability" (GitHub
private vulnerability reporting), which reaches the maintainers through
a private advisory channel. Include what you observed, the PostgreSQL
version and repository branch, the extension version (tag), and, if you
can, steps to reproduce the behavior.

Please give the maintainers time to assess the report and coordinate a
fix and disclosure before any public discussion.

## What is not a vulnerability

Low-severity configuration questions -- GUC tuning, which library to
preload, missing grants on the view -- are fine as regular issues or in
GitHub Discussions. If in doubt, use the private channel.
